# Local validation — 2026-09-10

For the latest structural performance results, see September 17 below. Earlier
sections retain the evidence for the engine, collision, lighting, and landscape milestones.

Validated on the available macOS ARM64 host. Windows and Linux CI definitions are included, but those builds and cross-platform sessions have not been run here.

- Native editor, player, server, cooker, and all three test executables compiled against the pinned dependencies.
- `ctest --test-dir build --output-on-failure`: 3/3 passed. Includes optimized voxel geometry/import checks, persistence/transactions/structural failures, and ENet replication.
- Network tests exercise a host and three clients, edits, late joining, and a UDP impairment proxy with 100 ms round-trip delay, jitter, reordered packets, and 2% loss. This is a bounded regression test, not a long-session performance qualification.
- A project generated by `aspera_cooker --new-project` ran for 60 offline server ticks.
- Both sample projects launched in the native player. The editor and exported demolition game rendered successfully using Metal; screenshots were inspected.
- Export contains the player, server, shaders, Lua game content, launch scripts, and dependency notices.

The offline benchmark with two million structural voxels, 5,400 structural nodes, and 500 additional single-voxel dynamic bodies reported CPU tick p50 **0.827 ms**, p95 **1.580 ms**, and p99 **1.622 ms** over 120 ticks. This short steady-state run does not measure sustained destructive editing, rendering, startup worst-case latency, or the requested 10,000-node workload. It does not establish the target hardware performance gates.

See [implementation status](STATUS.md) for the remaining release requirements. In particular, the current structural load solver is an approximation, player prediction uses sampled dynamic collision, and render/collision rebuilds remain object-granular.

## Quarry Demolition and player sessions

The bounded co-op slice is exercised with the following commands from the
repository root:

```sh
# Offline scene/script and save smoke
./build/aspera_server --project games/quarry-demolition --no-network --ticks 120 --save /tmp/quarry.sav

# Listen host plus remote clients
./build/aspera_player --project games/quarry-demolition --host --port 24680
./build/aspera_player --project games/quarry-demolition --connect 127.0.0.1 --port 24680

# Dedicated authority
./build/aspera_server --project games/quarry-demolition --port 24680

# Packaged build
./build/aspera_cooker --package games/quarry-demolition out/quarry-demolition
./out/quarry-demolition/Play.sh
```

Acceptance checks cover four assigned player IDs, safe recovery at each authored
spawn, grounded movement through the apron and post-collapse rubble, authoritative
four-metre damage/build rays, late join during a collapse, disconnect cleanup, and
host-only round reset. The objective is checked from material counts: only IDs 2
and 3 contribute to the 68% works denominator, ID 4 supplies core integrity, and
the build material (ID 5) is excluded. Player state is transient, protocol 4 is
required, and save/cooked-asset formats remain version 3.

Local validation on 2026-10-08:

- The native desktop targets build, all nine CTest suites pass, and the core-only
  build passes both tests.
- Controller tests exercise walking, diagonal speed, jumping, ceilings, slopes,
  steps, moving supports, light debris, edited collision geometry, tool reach,
  one-shot actions, publication-time construction clearance, blocked recovery,
  and bounded prediction history.
- The quarry test verifies four clear grounded spawns, an initially connected
  structure, physical rubble after staged support removal, core survival,
  construction-independent scoring, and shared victory state.
- Networking checks cover listen/dedicated ownership, manual/bounds recovery,
  project reload, late player poses, and world snapshot resets under impairment.
  Stationary prediction converges within 0.1 m after one second at 100 ms RTT,
  jitter/reordering, and 2% loss.
- A 600-second four-player loopback soak completed 23,760 simulation frames and
  39 project/round resets with bounded prediction history and a complete roster.
  The final transport ordering changes were subsequently checked by the focused
  network regressions. This is a stability soak, not a 60 FPS performance result.
- Finite Metal player and editor lifecycle smoke tests passed; captures were
  inspected. The quarry server completed 120 offline ticks and saved its world;
  the native cooker produced a macOS package.

Reproduce the soak with `./build/network_tests --player-soak-seconds 600`.
Logs, captures, and the local package are retained in `out/player-validation/`.
Dynamic debris prediction remains approximate; target-hardware qualification and
native Windows/Linux runtime evidence remain separate release requirements.

## Collision destruction — 2026-09-11

The rebuilt macOS targets pass all three CTest suites (2.49 seconds locally).
Additional regression cases cover:

- Material toughness round-trips and version-1 world/cooked-asset defaults.
- Release/launch validation, including paused and jointed objects.
- Actual static and moving-body impacts, including a 50 m/s strike on a single-voxel target.
- Increased damage with speed and mass, reduced damage with higher toughness, and partial damage accumulation.
- Resting contact stability, rotated contact coordinates, and an impact deferred around a concurrent paint transaction.
- A 300-pair contact burst: at most 256 pending records, at most 64 processed per tick, and observable overflow.
- Remote release commands and committed impact destruction through the UDP impairment proxy, followed by a fourth participant joining the damaged world.

The Collision Lab was run headlessly for 180 ticks and rendered in the native
player. Inspection confirmed a timber support separates into a falling section,
a dropped steel block chips its timber target, and the resting stack remains
undamaged. The editor renders the release/launch controls, toughness control,
and impact counters. A standalone Collision Lab package was generated.

These are bounded development checks. Impact response uses Jolt's pairwise
impulse estimate and the engine's approximate structural solver. Dense simultaneous
collisions and expensive object-granular collision preparation still require
performance tuning; no target-hardware or cross-platform performance claim is made.

The large fixture exposed a preparation stall caused by damage-only object
revisions rebuilding unchanged voxel geometry. Mesh, GI-source, structure, and

### Sustained M3 measurements

Completed twelve native 1920×1080 Balanced runs with GI and bloom enabled:
three 60-second measurements per scene, each after five seconds of warm-up.
All twelve passed the local frame cadence gate. The retained reports contain
every run's CPU/GPU p50/p95/p99, memory estimates, and raw frame/pass data.

| Scene | Frame p95 range across 3 runs | GI interval p95 range |
|---|---:|---:|
| Demolition | 8.09–8.15 ms | 5.93–5.95 ms |
| Construction | 7.57–7.65 ms | 5.44–5.45 ms |
| Collision | 9.25–9.27 ms | 6.77–6.79 ms |
| 2,040,800 structural voxels + 500 bodies | 8.33–9.45 ms | 5.77–6.53 ms |

Peak texture allocation was **299.0 MiB**. The overlapping GI estimate was
approximately **102.9 MiB**. These are renderer allocation estimates, not total
process memory. The larger spread in the final fixture is retained as measured;
there is no thermal or operating-system telemetry to establish its cause.

The approximate **4 ms GI budget was missed**. Inspection of the large fixture's
first run found near/far injection p95 of 0.760/0.569 ms, temporal resolve 0.434
ms, and bilateral upsampling 0.318 ms. Directional tracing samples three lobes at
two neighboring levels, up to four cones × 24 steps; volume boundaries add
near/far sampling. Full GI intervals also include mip work and synchronization.
Raster-stage overlap prevents attributing the remainder by adding per-view
durations. No requested effect was disabled to obtain these measurements.

The suite preceded the final capability/allocation checks and qualification
reporting hardening, which do not change shader or steady-state render work.
A post-review audit of retained raw timestamps passed the stricter coverage
requirement in every run (99.87–100% unique frame coverage); suite commands used
default bloom. The final native lifecycle smoke and benchmark regression tests
exercise the hardened build.

## Structural preparation and collapse — 2026-09-17

Validated on this macOS ARM64 host using the existing RelWithDebInfo build.
The final benchmark ran five independent default-landscape and quarry scenarios:
537,230 generated voxels, 32 occupied chunks, and a 7,718,599-byte snapshot.

| Measurement | Samples | p50 | p95 | Maximum |
| --- | ---: | ---: | ---: | ---: |
| Generation and derived validation | 5 | 364.752 ms | 509.681 ms | 509.681 ms |
| First simulation tick | 5 | 31.512 ms | 38.480 ms | 38.480 ms |
| Subsequent idle ticks | 40 | 0.385 ms | 8.769 ms | 10.161 ms |
| Paused edit completion | 60 | 17.116 ms | 38.294 ms | 52.636 ms |
| First tick after twelve digs | 5 | 9.950 ms | 12.912 ms | 12.912 ms |
| Quarry collapse simulation ticks | 80 | 7.688 ms | 32.547 ms | 37.138 ms |

All three requested local gates passed: collapse p95 below 33 ms, maximum below
100 ms, and paused-edit completion p95 below 50 ms. Every run detached all 1,152
roof voxels on simulation tick 16. Timing is measured per simulation tick;
generation, snapshot encoding, and paused-command completion are not folded into
the collapse distribution. The support cut commits while paused, preserving the
original deterministic scenario. This does not measure live-command contention,
sustained rendering frame cadence, networking latency, or larger landscapes.

The September 16 baseline measured a 2,430.91 ms maximum quarry tick and a
1,386.77 ms first post-dig tick. The final five-run maxima are approximately 65×
and 107× faster, respectively. The baseline was one run, so these ratios are
comparisons of recorded workloads rather than statistical confidence intervals.

The final worst tick spent 28.946 ms in structural preparation, 0.244 ms in
connectivity, 0.228 ms solving loads, 3.175 ms preparing fragments, 0.867 ms in
collision preparation, and 1.712 ms in physics publication. Structural stage
timings are exclusive of nested preparation; total physics time includes
publication and the physics step. Remaining time includes cache bookkeeping and
normal engine work. That tick rebuilt 81 regions, scanned 295,936 cells, and
reported 4,093 reused regions and approximately 34.5 MiB of structural cache data.
Cache memory is an estimate, not process RSS or a peak-allocation measurement.

Validation:

- Full native build and all **7/7** CTest suites passed. Core-only tests passed
  **2/2** and headless server tests passed **6/6**, including networking.
- The frozen pre-optimization solver is linked only into the new differential
  test target. Tests compare deterministic node/bond ordering, 3D edits across
  signed 8/32-cell boundaries, fatigue recovery/reset, material refresh, fragment
  ownership/velocity, joints, and fracture decisions.
- Cache tests cover generation seeding, unchanged/local/anchor-only updates,
  deletion/reset, repeated budget rejection, and allocation failures during
  multi-fragment collision-cache staging. Disconnected 12,000-node sources split
  into valid 6,000-node fragments; oversized connected sources still reject.
- The native 96-frame editor lifecycle smoke passed lighting and terrain
  generation, undo/redo, selective chunk rebuilding, cancellation, scene changes,
  resize, and minimize/restore. Its final capture was 2048 × 1280 pixels.
- Changed C++ files passed formatting checks.

Raw benchmark output and the editor capture are retained under
`out/structure-performance-validation/`. Reproduce with
`./build/landscape_engine_tests --benchmark --benchmark-runs 5`.
The global graph load solve, rotating-fragment cell traversal, whole-object edit
copies, and save/network encoding remain in place. These results meet the chosen
finite-map CPU latency targets; they do not qualify a general 60 FPS release gate.


## Optional native path tracing — October 8–9, 2026

Implementation and local validation used the 8-core Apple M3. The default
renderer remains bgfx raster; path tracing is opt-in with `--renderer path-traced`.
Both native Metal and Vulkan C++ backends compile in the local build. All native
Metal shader pipelines compile through the device's runtime compiler; Vulkan
modules compile for Vulkan 1.2 and pass SPIR-V validation. Offline Metal compilation
was unavailable because this host has Command Line Tools rather than full Xcode;
packaged Metal sources provide the tested runtime-compilation fallback.

Local correctness evidence:

- All ten CTest cases pass. The existing loopback network case required execution
  outside the sandbox to bind its local test port.
- Metal API validation passes native renderer smoke/capture runs and the 96-frame
  path-traced editor lifecycle, including lighting/material undo/redo, topology
  edits, quality/size changes, teleports, minimize/restore, and scene replacement.
- The original raster bounce checks and raster editor lifecycle continue to pass.
- A native stress-overlay smoke with 4,096 regions (more than 65,535 ImGui
  vertices) passes Metal API validation using segmented vertex offsets and the
  same stress-color palette as raster rendering. Reference-camera movement from
  held keys is disabled while exact-sample captures are running.
- The new capture checker verifies equivalent 256-sample images at 1 versus
  16 samples per frame: mean channel difference `0.0000417` on the 0–255 scale,
  with maximum channel difference 1 from rounding.
- A 257-sample capture at 64 samples per frame exercises the partial final batch.
  Every pixel inside the closed, unlit room is black (maximum channel 0).
- The off-camera red card reflects in the smooth metal sample. Its central
  reflection region has mean RGB `(47.36, 2.80, 2.25)`; the card is behind the
  camera at `(-1.4, 1.2, -3)`.
- One- versus six-bounce captures in the diffuse bounce fixture differ by mean
  channel value `8.5122`, demonstrating additional light transport. Reference
  captures intentionally retain Monte Carlo noise; ordinary gameplay denoises.
- A denoised Quarry Demolition gameplay preview is retained with the other
  captures. The final shaders also handle equal inner/outer spot-light cones.

The sustained October 8 measurements use native **1920×1080**, one sample per
pixel per frame, six surface interactions, temporal denoising, five 3×3 spatial
passes, and bloom. Each scene ran once for 60 measured seconds after 5 seconds

| --- | ---: | ---: | ---: | ---: |

**The M3 does not meet the 33.3 ms / 30 FPS qualification target.** These are
single sustained development runs, not three-run qualification. Resolution,
ray count, bounce limit, and effects were retained rather than reduced to pass
that target. Spatial filtering was optimized from a 5×5 to 3×3 kernel while
retaining all five passes. Native Metal frame timing uses the command interval
envelope because individual pass intervals can overlap on tile GPUs.

Retina benchmark windows are sized in logical points before creation to produce
the requested physical pixel dimensions. Earlier clamped-window development
measurements were rejected by the resolution gate and are retained separately.

Raw captures, logs, frame/pass CSVs, hardware/source fingerprints, and reports are
in `out/path-tracing-validation/`; sustained data is in its `sustained-m3/`
subdirectory. Reproduce correctness with `tools/check_path_tracing.py`, and
performance with `tools/run_render_benchmarks.py --renderer path-traced`.

Native Windows/Linux Vulkan execution, Vulkan validation-layer runs on suitable
hardware, RTX 3060 12 GB performance measurements, and full three-run hardware
qualification remain external requirements. CI now installs Vulkan development
packages for Windows/Linux builds; defining those jobs is not evidence that
remote CI or native Vulkan runtime validation has passed.
